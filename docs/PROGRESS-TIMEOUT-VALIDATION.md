当前状态：Owner 已确认最终功能基线在真实 Tavern 可正常使用和安装扩展，进入最终发布 Gate；尚未发布。以下保留调查过程与阶段性测试结果，早期 TEST ONLY 状态不再代表当前功能验收状态。

历史背景：此前在真实 Tavern 观察到持续接收 Polisher 附件，但 Hub 60 秒附件总时限终止传输。Owner 已授权改为以无进展超时为主、有界最终总时限为兜底。此改动是实际下载行为变化，不是纯诊断。

## 候选规则

| 阶段 | 限制 |
| --- | --- |
| GitHub 直连附件 | 5 秒，包含正文；字节进展不延长，失败后现有安全 Relay 接管 |
| 中转响应等待 | 最多 60 秒；未收到可用正文时不会使用 10 分钟盲等 |
| 中转安装包正文 | 连续 30 秒未收到非空新字节则取消；每次有效字节重置此计时 |
| 单个安装包下载及 Asset digest 校验 | 最终 10 分钟上限，无法被进展重置 |
| Asset digest 校验 | 独立最多 15 秒，同时受父时限/取消约束 |
| Release 查询、机器元数据 | 保持原 15 秒预算 |
| 宿主更新保存确认 | 保持原有单独预算 |

30 秒和 10 分钟是验收候选参数，不宣称为最优值；不是先前 105/300 秒 budget-candidate。上限避免持续极少字节无限占用安装锁。中转 fetch 的同一个子 signal 在响应头及正文全程保留父取消关联，清理定时器和 reader；未增加新的代理、镜像、持久缓存或额外网络请求。

Registry 0.6.1 先收齐并校验 GitHub 附件，再发送浏览器响应。本次只调整 Hub 的接收策略；服务器自身 upstream 60 秒/operation 90 秒及反向代理规则未修改。Hub 进展表示浏览器实际收到的字节，不能展示 Registry 尚未返回响应时的服务器内部进度，也不能避免独立的上游/代理超时。慢速所在链路仍未定位。

## 界面

扩展中心返回按钮上方悬浮显示工具名称、字节百分比、已下载/总大小、最近约 5 秒平均速度和取消按钮。完成后短暂发光，约 1.2 秒后开始收回并隐藏；遵守减少动态效果偏好。没有数据时速度下降至零，提示等待；低于 50 KB/s 提示慢速但仍在继续，这个展示阈值不影响取消判定。速度统计不向服务器上报。

安装包检查阶段完成后提供取消下载按钮，写入开始时隐藏，避免误导为可以撤销已写入脚本。取消或超时均必须通过原 signal 检查，禁止晚到的数据引发写入。成功前仍执行大小、Asset digest、Package/content SHA-256、Manifest/身份、Release 重读检查。下载 100% 不等于安装 100%；下载完成后仍显示校验/写入阶段。

下载逻辑同时用于 Managed Package 的安装和更新；本轮速度及取消界面接入新安装流程。Hub 自更新流程未改动。Runtime Compatibility 与 Managed Package Compatibility 分别验收。
